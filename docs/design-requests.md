## 미해결 요청 상세

### DR1. 지도(B4) 마커 밀집·클러스터 규칙
- **문제**: 처음 화면에서 한반도 전체와 중국·일본까지 보이고, 가격 칩 100개가 서울·경기 근처에서 서로 겹쳐 '10,0…', '1', '…료' 처럼 잘려 읽을 수 없다. Figma 419:2 는 마커 7개, 589:2 는 5개만 그려서 겹침·밀집·100개 상한 상태가 없다. 419 는 꼬리가 있고 589 는 '꼬리 없음'이라고 해서 두 프레임이 다르다 (코드는 589 기준).
- **현재 FE**: 가져온 행사를 모두 칩으로 그린다. '행사가 많아 100개까지만 보여요…' 안내와 '지도 영역 안 100개' 문구는 코드에만 있고 프레임이 없다.
- **요청**: 처음 보이는 영역(데이터에 맞춤, 최소 줌), 겹칠 때 묶음 방식(개수 말풍선 모양과 기준 줌), 겹침 순서(선택한 마커가 위), 멀리서 볼 때 가격 없는 점 표시, 100개 안내 문구와 프레임을 정해 달라. 419 가 589 로 대체되었는지도 알려 달라.

### DR2. 길찾기 D1 버스 여러 개 행과 시외 구간 단계
- **문제**: 586:117 은 버스 한 대(24번)만 그렸다. 한 구간에 노선이 여러 개(예: 24, 100, 200)이거나 이름이 긴 경우(광역급행9401)의 모양이 없다. 열차·고속버스·시외버스 단계는 BE가 '이동' 만 줘서 어디서 어디로 가는지 알 수 없다.
- **현재 FE**: 원 안에는 첫 노선만 쓰고 나머지는 '+N' 알약(검정, 오른쪽 위)으로 표시한다. 칩은 노선마다 하나씩 줄바꿈된다. 원 안 글자는 3자 이하 12px, 4자 10px, 5자 이상 9px 로 줄였다. 칩 글자는 '버스 24' 가 아니라 '24' 만 쓴다(접근성 라벨에만 '버스'). 시외 구간은 회색 원과 '이동' 글자로 나온다. 이 중 시안에 있는 값은 없다.
- **요청**: 노선이 여러 개일 때의 원 표시(첫 노선·개수·아이콘 중 택일)와 '+N' 모양, 칩 최대 개수와 넘칠 때 규칙, 긴 이름 자르는 폭, 칩 글자('버스 24' 인지 '24' 인지), 환승·하차 줄에 노선이 많을 때, 시외 구간 단계의 모양을 그려 달라.

### DR3. 프로필(E5~E7) 읽기 전용 상태와 사진 업로드 상태
- **문제**: 시안 E5 는 이름 입력(3/10 글자 수)과 취소·저장이 있는 편집 화면이다. BE에는 닉네임 수정 API가 없고 사진만 바꿀 수 있어서 FE는 이름·이메일을 읽기 전용으로 두었다. 그래서 제목('프로필 편집' ↔ '내 프로필'), 버튼('취소·저장' ↔ '뒤로·로그아웃'), 안내 문구('카카오 계정 이메일은 바꿀 수 없어요.' ↔ '이름과 이메일은 카카오에서 바꾸면 다음 로그인 때 반영돼요.'), E1·E2 버튼('프로필 편집' ↔ '프로필 보기')이 다르다.
- **시안에 없는 상태**: 업로드 중(FE: 배지 흐리게 + '사진을 올리고 있어요'), 오류(FE: 아바타 아래 한 줄), 올릴 사진 미리보기·자르기, 'PNG/JPG/WEBP 10MB' 안내, 카카오 사진으로 되돌리기 항목(API는 지원), 모바일에서 메뉴 위치(left -58 이 화면 밖으로 나감).
- **요청**: 닉네임 수정을 넣을지 결정하고(넣으면 BE에 `PATCH /api/users/me` 요청), 읽기 전용 프레임과 위 상태들을 그려 달라.

### DR4. 모바일 폭
- **문제**: 시안은 데스크톱(1200px 컨테이너)뿐이다. 390px 에서 헤더 검색창이 30px 로 줄고 '로그인' 글자가 세로로 쪼개지며(로/그/인), 모든 화면이 가로로 넘친다(603px). `main` 브랜치에서도 같은 값이라 이번 변경과 무관한 기존 문제다.
- **요청**: 모바일을 지원할지 정하고, 지원하면 헤더(메뉴·검색·로그인)와 주요 화면의 모바일 시안을, 안 하면 최소 지원 폭과 그 아래에서의 안내를 정해 달라.

### DR5. 헤더 유틸 아이콘 위치 기준
- **문제**: 캘린더·지도·찜 아이콘(408:26, 408:33, 408:39)은 24칸 기준으로 그린 벡터를 22×22 프레임에 크기 조정 없이 넣어(넘침 표시) Figma 에서 글리프가 중심보다 1px 오른쪽, 찜은 2px 아래다. 크기도 22/24 로 줄인 것보다 약 8% 크다. FE는 24칸 그림을 22px 로 줄여 중앙에 둔다. 검색·카카오 아이콘(18px)은 정확히 일치한다.
- **요청**: 의도한 쪽을 알려 달라. Figma 가 정답이면 FE는 아이콘의 viewBox 를 22 로 바꾸고 넘침을 허용하겠지만, 그러면 아이콘이 눈에 띄게 한쪽으로 치우친다.

### DR6. 푸터 변형 3종과 남은 링크
- **문제**: A1(408:1170)·F1(437:67)은 글자 12px, 간격 18, 위아래 여백 34/42, 링크 위쪽 정렬이고, B3(621:98)은 13px, 간격 20, 여백 32/40, 로고와 링크 세로 가운데 정렬, 이용약관 Medium·개인정보처리방침 Bold 다. A1·F1 에는 서비스 소개·문의하기까지 4개 링크가 남아 있어 DR6(11/21 결정)과 모순된다. 지금 FE는 B3 의 크기와 A1 의 여백·정렬을 섞어 쓴다. /terms 에서 현재 페이지가 이용약관인데 개인정보처리방침만 Bold 인 것도 어색하다.
- **요청**: 푸터를 하나로 정해 모든 프레임에 반영해 달라(링크 2개).

### DR7. 메인 배너 화살표 버튼, 사진 위 글자
- **문제**: 배너 좌우 화살표는 시안에 없는데 FE에 지름 40px 흰 원 두 개('‹' '›', 배너 가장자리에 걸침)가 있다. 사진이 밝으면 배너 위 작은 라벨('이번 주말 · 서울')이 어두운 덮개 시작 위치(카드 높이의 40%)보다 위에 있어 읽기 어렵다. 시안은 그라데이션 배경만 그렸다.
- **요청**: 화살표(크기·위치·hover·focus)를 그리거나 빼 달라. 사진 배너 글자의 덮개 또는 그림자 규칙을 정해 달라.

### DR8. A3 로그인 하단 문구와 링크
- **문제**: 시안 410:302 는 '로그인하면 이용약관 및 개인정보처리방침에 동의한 것으로 봐요.' (두 단어 밑줄). FE는 '처음 로그인하면 이용약관·개인정보처리방침 동의 화면이 이어져요.' (링크 아님)다. 실제 동작은 첫 로그인에만 동의 화면이 나온다.
- **요청**: 최종 문구와, 약관 단어를 /terms·/privacy 링크로 만들지 정해 달라.

### DR9. B3·F1 프레임 폭 기준과 로그아웃 상태 404
- **문제**: B3(621:2)는 좌우 여백 120(로고 x=120), A1·F1 은 1200px 컨테이너와 여백 24(로고 x=144)다. FE는 144로 통일했다. F1(437:2)은 로그인한 헤더(아바타 '민')와 예전 4링크 푸터를 보여 준다.
- **요청**: B3 가 느슨하게 그려진 것인지 확인하고, 로그아웃 상태 F1 프레임을 추가하거나 확인해 달라.

### DR10. 기획전 카드(A6)
- **문제**: 칩 높이가 시안 22px(14px 글자+위아래 4)인데 글줄 높이 기준(Figma `normal`≈1.2배, 브라우저 1.5배)이 달라 FE에서 맞추려면 값을 직접 지정해야 한다. 카드 높이 168px 이 고정이라 제목이 긴 카드(예: 12자 '무대 앞에서 보내는 저녁')가 좁은 폭에서 잘릴 수 있다. 태그 수 불러오는 중·실패 상태, 10개가 모두 0건일 때 빈 상태가 없다. 시안 A8(415:2)은 6장 3열×2줄이고 408:2 와 619:2 는 10장 5열×2줄이다.
- **요청**: 최종 배치(A8 대 619:2), 칩 높이와 글줄 높이 기준, 긴 제목 처리, 불러오기·빈 상태를 정해 달라.

### DR11. 아바타 이니셜 규칙
- **문제**: 시안 헤더와 프로필 아바타는 '안민영'에 '민'을 쓰고, 리뷰 아바타는 '김서연'에 '김'을 쓴다(성). FE는 첫 글자('안')를 쓴다.
- **요청**: 한 가지 규칙을 정해 달라.

### DR12. 빠진 상태
- **문제**: (1) E3 내가 쓴 리뷰가 0건일 때 프레임 없음(FE: 작은 회색 사진 아이콘. E2 는 84px 타일). (2) 캘린더에서 찜이 없는 달 프레임 없음(FE: 60px 타일+검색 아이콘). (3) 리뷰 작성 폼의 별점 미선택 상태와 '4.5점' 라벨(시안: 18px Bold '4.5점', FE: '별점을 선택해 주세요'). (4) 사진 추가가 시안 422:213 은 '사진 추가 (최대 5장)' 고스트 버튼이 등록 버튼과 같은 줄에 있고, FE는 80px 점선 칸에 0/5 와 안내 한 줄이다 (DR1과 연결).
- **요청**: 해당 프레임을 추가하거나 FE 방식을 확정해 달라.

### DR13. 토스트 위치 기준
- **문제**: E7(436:2)의 토스트는 1356px 높이 페이지 프레임 안 절대 위치(x=626.5, y=1173.9)라 화면 기준 위치가 아니다. FE는 화면 아래 32px, 가운데에 고정한다.
- **요청**: 화면 하단 여백과 푸터 위에 놓을지 등 위치 기준을 알려 달라.

### DR14. 리뷰 수정 모달 상태와 사진 크기
- **문제**: 수정 모달(E4)에 등록 중·실패 상태가 없다(메모는 C2 를 따르라고 하지만 모달에는 재시도 버튼 자리가 없다). 사진 힌트 줄('JPG·PNG·WEBP, 한 장에 10MB까지, 최대 5장')과 선택 오류 안내도 시안에 없다. 수정 모달 썸네일은 72px, 작성·목록은 80px 인데 메모는 80px 만 말한다. 리뷰 등록이 사유가 있는 오류(이미 작성함 409, 이미지 저장소 장애, 한도 초과)로 실패할 때 부제 문구가 시안에 없다(FE는 서버 사유를 부제에 보여 줌).
- **요청**: 위 상태와 썸네일 크기, 사유별 문구를 정해 달라.

### DR15. A7 약관 동의 화면
- **문제**: 시안에 취소 링크가 없는데 FE에는 있다(로그아웃한다). 저장 실패 상태에서 시안은 '필수 항목 2개에 동의하면…' 안내를 뺐고 버튼 위 간격이 8px(FE 14px)이다.
- **요청**: 취소 링크를 유지할지와 실패 상태 간격을 확인해 달라.

### DR16. 소소한 화면 정리
- **검색창이 두 개**: /events 와 /map 에서 헤더와 페이지 안에 같은 '행사 검색' 입력이 둘이다. 하나만 둘지 정해 달라.
- **'다가오는 순' 중복**: /my/bookmarks 에서 왼쪽 라벨과 오른쪽 선택된 정렬 탭에 같은 글자가 두 번 나온다.
- **상세 미니맵**: 높이 170px 안에서 아래 주소 알약이 지도 글자를 가린다. 알약을 지도 밖으로 빼거나 높이를 키울지 정해 달라.
- **조회수 줄**: '조회 N' 이 조회수가 있는 카드에만 나와 카드 높이가 들쭉날쭉하다. 항상 자리를 둘지 정해 달라.
- **노선 번호 중복**: 지하철 단계에서 원 안 '4' 와 칩 '4호선' 이 같은 정보를 반복한다.
- **간격 기준 (FE는 아직 안 고침)**: ① 상세 사이드바 위 간격 — Figma 422:137 은 히어로 바로 아래(0)인데 FE는 22px 띄움. 본문 칸이 22px 위 여백을 따로 갖고 있어 Figma 쪽 실수일 수 있다. ② 홈 섹션 사이 간격 — 실제 화면 측정으로 Figma 가 9~11px 더 넓다(75 대 64px). 시안의 패딩 값이 아니라 측정값이라 확인이 필요하다. ③ 지도 줌 버튼 위치 — 419:252 는 지도 아래 14px, 지금 FE는 26px. 589:2 에는 버튼이 없어 어느 프레임이 기준인지 알려 달라.
- **토스트가 모달 위에 남음**: 리뷰 등록 성공 토스트가 수정 모달·이탈 확인 모달 위에 몇 초 남는다. 모달이 열리면 토스트를 닫을지 정해 달라.
