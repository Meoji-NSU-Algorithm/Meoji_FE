# QA 보고서 2026-11-22

대상 브랜치 `feature/be-sync-profile-directions` (백엔드 반영, 프로필 사진 업로드, 길찾기 버스 여러 개, Figma 3차 수정, 디자인 검수 수정).

## 환경과 방법

- FE: Vite 5173번(카카오 지도는 이 포트에서만 로드), `/api`는 5001로 프록시.
- 브라우저: Playwright + 시스템 Chrome. 로그인이 필요한 화면은 **사용자가 직접 카카오 로그인**한 세션을 임시 폴더에 저장해 사용했고, 보고서 작성 후 삭제한다. 토큰을 만들거나 입력하지 않았다.
- 역할을 나눠 서브에이전트가 진행했다: 개발(백엔드 반영, 프로필, 길찾기, 3차 수정), 디자인 검수 2회(로그인 전·후), QA(직접 조작).
- 자동 검사: Vitest 260개, `tsc -b`, oxlint, `vite build` 모두 통과.

## 외부 호출과 쓰기

- 외부 API: 길찾기 **정확히 3회**(대중교통·자동차·도보 각 1회, 행사 718, 출발지 서울역). 재시도 없음. KOPIS·TourAPI 호출 없음. 응답은 저장해 재사용했다.
- 쓰기: 찜(행사 716·718·719)과 텍스트 리뷰 1건(행사 718)을 만들었다가 모두 삭제했다. 최종 상태는 시작과 같다(찜 0, 리뷰 0).
- 프로필 사진(1차 QA): 유효한 이미지는 올리지 않았다. 깨진 PNG 1건만 보냈고 서버가 저장 전에 400으로 거절했다.
- 프로필 사진(사용자 승인 후 1회 테스트): 정상 PNG 1장을 올렸더니 서버가 503 `IMAGE_STORAGE_UNAVAILABLE` 로 실패했다. BE 로그는 R2 `PutObject` 의 `AccessDenied` 로, 키에 쓰기 권한이 없는 것이다(BE 요청서 해결 표의 'R2 쓰기 권한'). 아무것도 저장되지 않아 버킷에 테스트 파일은 남지 않았다. 이어서 화면의 '기본 이미지로 변경'을 눌러 200, 토스트, 이니셜 복귀를 확인했다. 계정은 사진 없는 시작 상태(사진 없음)로 되돌렸다. 시작 시점의 저장 값이 kakao 인지 default 인지는 알 수 없어 `kakao` 로 되돌렸고, 화면은 시작과 같다.

## 프로필 사진 업로드 재테스트 (R2 권한 수정 후, 사용자 요청)

R2 토큰 권한을 고친 뒤 백엔드를 새로 시작하고 같은 테스트를 다시 했다. 작은 정상 PNG(256×256) 1장을 사용했고, 마지막에 '기본 이미지로 변경'으로 지워서 버킷에 테스트 파일을 남기지 않았다.

| 항목 | 결과 |
|---|---|
| 업로드 | PASS: 저장 토스트 '프로필을 저장했어요!' |
| 아바타·헤더·마이페이지 카드 | PASS: 모두 사진으로 바뀜, 원형으로 잘림, 카메라 배지는 오른쪽 아래 흰 테두리 |
| 새로고침 후 유지 | PASS: 서버 값이 `https://` R2 주소, 화면에 그려짐(256×256) |
| 사진 URL | PASS: https(혼합 콘텐츠 아님), 만료 3600초(`S3_PUBLIC_URL` 비어 있음) |
| 기본 이미지로 변경 | PASS: 200, 토스트, 이니셜 복귀, `profile_image=null` |
| 계정 복구 | 시작 상태(사진 없음)와 같음 |

참고: 같은 검사 스크립트가 사진 URL을 `fetch` 로 직접 요청했을 때는 `Failed to fetch` 가 났다. 이는 R2 버킷에 CORS 규칙이 없어서 생기는 현상으로, `<img>` 로 표시하는 데는 영향이 없다(화면에서는 정상 표시). FE가 사진 URL을 `fetch` 로 읽는 일은 없다.

## 확인하지 못한 것

- **사진 URL 1시간 뒤 만료 동작**: URL의 만료 값이 3600초임은 확인했지만, 실제로 1시간이 지난 뒤 아바타가 깨지는지(FE는 `me` 를 다시 불러오기 전까지 같은 URL을 씀)는 기다려 보지 않았다. `S3_PUBLIC_URL` 을 설정하면 만료되지 않는다.
- 리뷰에 사진을 첨부해 등록하는 성공 경로(프로필과 같은 저장소 설정이라 가능해졌을 것으로 보이나 이번에는 시도하지 않았다).
- 운영 서버의 R2 키 권한.
- 자동차 길찾기 성공 화면, 실제 ODsay 응답의 버스 여러 개 단계.
- 모바일·태블릿 폭(시안 없음, `main` 에서도 같은 문제). 디자인 요청 DR4.
- 카메라 촬영(`capture`)의 실제 기기 동작.
- **운영 환경**: HTTPS, 운영 도메인의 CORS, 카카오 운영 리다이렉트 URI, 운영 DB 마이그레이션, Vercel 배포. `docs/deploy.md` 의 6번 체크리스트로 배포 후 확인한다.
- 캘린더 일정 칩 클릭, 지도 확대 후 핀 겹침.
